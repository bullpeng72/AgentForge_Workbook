# background-real-verification — 실측 배치 실행 절차

AgentForge Part VII~VIII에서 8번 이상 반복된 절차다(gate_run_1~8, 재현성 체크,
CI 첫 실행 등). 매번 같은 실수 유혹이 있었다 — "곧 끝날 테니 결과를 미리 요약해서
보고할까" — 하지만 실제 LLM 호출은 예측 불가능하게 오래 걸리고(같은 배치가
어떤 날은 2분, 어떤 날은 8분), 끝나기 전에 점수를 언급하면 십중팔구 틀린다.

## 절차

1. 실측이 필요한 이유를 먼저 명확히 한다 — mock으로 충분한지, 정말 실제 호출이
   필요한지 구분한다(`evidence-based-gate-fix`의 6단계에서 "mock 아님"을 요구하는
   지점).
2. 예상 소요시간이 짧으면(수십 초) 포그라운드로 그냥 기다린다. **길면(수 분+)
   반드시 `run_in_background: true`로 실행한다** — 타임아웃으로 죽이지 않는다.
3. 백그라운드로 넘어간 직후, 사용자에게 "지금 실행 중"이라고 짧게 알리고 멈춘다.
   **아직 나오지 않은 결과를 짐작해서 말하지 않는다** — "아마 잘 될 것 같다",
   "거의 다 됐을 거다" 같은 문장을 쓰지 않는다.
4. 완료 알림(task-notification)이 올 때까지 짧은 sleep 루프로 반복 확인하지
   않는다 — 알림이 오는 채널이 따로 있으므로 그냥 기다린다.
5. 알림이 오면 **그 즉시** 출력 파일을 읽고, 실제 값을 그대로 보고한다 — 좋은
   숫자가 나오길 기대하며 각색하지 않는다(fail이 나오면 fail이라고 말한다).
6. 결과가 예상과 다르면(예: 이전 시도에서 통했던 fix가 이번엔 재현 안 됨) 그
   차이 자체를 보고 대상으로 삼는다 — LLM 비결정성 자체가 유효한 발견이다.

## 완료 조건

- [ ] 긴 작업을 포그라운드에서 타임아웃까지 기다리게 하지 않았다
- [ ] 백그라운드 전환 직후 결과를 추측해서 말하지 않았다
- [ ] 완료 알림 전까지 sleep 폴링 루프를 돌지 않았다
- [ ] 알림 도착 즉시 실제 출력을 확인하고 보고했다(각색 없음)
